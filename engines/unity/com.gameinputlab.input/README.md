# Game Input Lab for Unity

Unity 2022.3 or later. Runs the same stick response, smoothing and touch handling as the Game Input Lab app, so a preset tuned on a phone feels the same in the game.

## Install

Package Manager ▸ + ▸ Add package from git URL:

```
https://github.com/lmj-labs/game-input-lab-engines.git?path=/engines/unity/com.gameinputlab.input
```

Or Add package from disk and pick `package.json` in this folder.

Works with the Input System package (1.4+, EnhancedTouch) or the legacy Input Manager. If both are enabled, the Input System is used.

## Use

**Component.** Add *Game Input Lab ▸ Virtual Joystick* to a UI object. Assign a touch **Area** (RectTransform) and optional **Stick Base** and **Knob**. Set a preset in one of three ways:

- Drop the app's JSON export on **Preset** (TextAsset).
- Paste the app's Unity C# export into the project and call `joystick.Config = MyJoystickPreset.Create();`.
- Edit the fields in the Inspector.

Read `joystick.Value` (length 0–1, +y up) every frame. `Released` reports why the stick let go.

**Your own input code.** Feed `StickTracker` every known touch once per frame:

```csharp
var tracker = new StickTracker(config) { Area = screenRect, UnitsPerPoint = VirtualJoystick.EstimatePixelsPerPoint() };
tracker.Step(touches, Time.unscaledDeltaTime * 1000f);   // touches: List<StickTouch>, screen pixels
Vector2 move = tracker.Output;
// Call tracker.Interrupt() when the app pauses or loses focus.
```

**Landscape layout.** The app's landscape labs export where each control sits (a fraction of the safe area, y up) and how big it is. Put a full-screen Canvas, then an empty child with *SafeAreaPanel*, then one RectTransform per control inside it. Load the JSON (`LandscapeLayout.FromJson(textAsset.text)`) or paste the C# export (`MyPadLandscapeLayout.Create()`), then:

```csharp
float units = SafeAreaLayout.UnitsPerPoint(canvas);
layout.Apply(safeAreaRect, "left", leftStickRect, units);
layout.Apply(safeAreaRect, "A", jumpRect, units, jumpHitRect);   // hit area optional
leftJoystick.Config = layout.Stick("left");
// Apply again when SafeAreaPanel.Changed fires.
```

## Behaviour

| Event | Output |
|---|---|
| Touch begins inside the area | Takes the stick. Fixed: centre of the area. Floating: where the finger lands. |
| Touch begins outside the area | Ignored for its whole life, even if it moves in. |
| Finger lifts (`Ended`) | Released. Eases to zero through smoothing. |
| System cancels the touch (`Canceled`) | Released. Zero at once. |
| Tracked finger ID missing from a frame, or begins again | Released as `Lost`. Zero at once. Never swapped for another finger. |
| App pauses or loses focus | Released as `Interrupted`. Zero at once. The same finger cannot resume. |

Units match the app: radius in points (pixels ÷ `Screen.dpi / 160`; set **Pixels Per Point Override** if a device reports a misleading DPI), dead zones in percent of the radius, smoothing in milliseconds. Smoothing uses unscaled time.

## Aim and the reference scene

`AimBehavior.Step(heading, move, aim, layout.Aim())` is the Dual Stick lab's aim rule: `Heading` is where the weapon points (`hold` keeps the last direction after release, `forward` turns to the way you move), `Firing` is true from the fire threshold, `MoveScale` slows movement while aiming. Call it every frame with the two stick outputs.

`SceneMotion.Step(state, stickOutput, deltaMs, sceneParams)` is the Joystick Lab scene: speed, acceleration, turn rate and a follow camera (`SceneState.Position`, `Heading`, `Camera`). A Joystick Lab export with a scene gives `SceneParams` through `CreateScene()` or `SceneParams.FromJson`.

`Tilt.Target(accel, neutral, config)` and `TiltStick` turn phone tilt into a stick output (Tilt Lab). Feed `TiltStick.Step` the gravity vector each frame in iOS convention: x right, y toward the top edge, z out of the screen, face up = z -1. Android's raw accelerometer has the opposite sign, so negate it there. Call `Calibrate` with the pose the player holds. Upright forward/back tilt cannot be measured from gravity alone.

`HapticPattern` is a custom vibration from the Haptics Lab: `IntensityAt(timeMs)`, `AndroidWaveform(out timings, out amplitudes)`, `LegacyTimings()` (phones that cannot set the strength) and `IosEvents()` (CoreHaptics events). `HapticPlayer.Play(pattern)` plays it on Android through `Vibrator` and `VibrationEffect` (needs the VIBRATE permission in the manifest and Android 8+ for the designed strengths). Unity has no CoreHaptics, so on iOS the player only calls `Handheld.Vibrate()`; feed `IosEvents()` to a CoreHaptics plugin for the real pattern. The editor does nothing. The Android calls were written without a device and have not been run.

## Consistency with the app

`Tests/Editor/Fixtures/joystick-vectors.json` is generated by the app repo (`npm run vectors`) from the app's own code. The EditMode tests replay it: response curve and stick output within 1e-4, smoothing and touch scenarios within 1e-3 (float against double). To run them, add the package to `testables` in the project's `Packages/manifest.json`.
