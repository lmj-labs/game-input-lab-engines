# Game Input Lab for Godot

GDScript reference implementation of the app's joystick, aim and layout rules (Godot 4.2+). It runs the same algorithm as the app; `tests/run_vectors.gd` replays the app's test vectors to check it.

## Install

Copy `addons/game_input_lab` into your project's `addons` folder. The scripts register their classes (`GILJoystickConfig`, `GILStickTracker`, ...) on their own; the plugin entry in Project Settings is not needed.

## Use

Export a preset or layout from the app (Godot GDScript tab). It writes a script such as `TwinStickJoystickPreset` that builds the config:

```gdscript
# On a node:
$Joystick.config = TwinStickJoystickPreset.create()   # GILVirtualJoystick, its rectangle is the touch area
var move: Vector2 = $Joystick.value                   # length 0 to 1, +y up

# Or in your own input code (touches are Dictionaries with +y up):
var tracker := GILStickTracker.new(TwinStickJoystickPreset.create())
tracker.area = Rect2(0, 0, 300, 300)
tracker.step([{ "id": 0, "position": Vector2(150, 150), "phase": "began" }], delta * 1000.0)
```

| Class | What it does | App (`src/`) |
|---|---|---|
| `GILJoystickConfig` | Parameters, limits, JSON | `components/joystickMath.ts` |
| `GILJoystickResponse` | Response curve, smoothing | `components/joystickMath.ts` |
| `GILStickTracker` | Finger ownership, cancel, lost ID, interrupt | `components/stickTracker.ts` |
| `GILVirtualJoystick` | Control node on top of the tracker; releases on focus loss | |
| `GILAimBehavior` | Weapon heading, fire threshold, slow while aiming | `components/aimBehavior.ts` |
| `GILSceneMotion` | Reference scene: speed, acceleration, turning, follow camera | `components/sceneMotion.ts` |
| `GILSafeAreaLayout`, `GILLandscapeLayout` | Safe-area placement, layout JSON (`orientation`: "landscape" or "portrait", lock the screen to match), `apply` to Controls | `landscape/layout.ts` |

Notes:
- Positions and outputs use +y up, like the app. `GILVirtualJoystick` flips Godot's screen y for you.
- A cancelled touch (`InputEventScreenTouch.canceled`) needs Godot 4.2 or newer.
- On desktop, turn on Project Settings > Input Devices > Pointing > Emulate Touch From Mouse to try the joystick with a mouse.
- `GILVirtualJoystick` is not covered by the vector tests (it needs a running scene); the classes under it are.

## Tilt

`GILTiltStick` (with `GILTiltConfig`, `GILTilt`) turns phone tilt into a stick output. Pass `Input.get_accelerometer()` in iOS convention (x right, y toward the top edge, z out of the screen, face up = z -1); negate it if your platform reports the opposite sign. Call `calibrate()` with the pose the player holds. Upright forward/back tilt cannot be measured from gravity alone.

## Haptics

`GILHapticPattern` is a custom vibration from the Haptics Lab: `intensity_at(time_ms)`, `android_waveform()`, `legacy_timings()` and `ios_events()`. `loop` repeats the pattern from the start when it ends (its total length is the period, so end it with a 0% step to leave a gap); `android_repeat()` is the matching Android `repeat` argument. `GILHapticPlayer` (a Node) plays it with `Input.vibrate_handheld`, one call per step: from Godot 4.3 each step has its own strength, before that every step above 0 is full strength. Godot cannot cut a vibration that has started, so `stop()` only keeps later steps from starting. A looping pattern runs until `stop()`. The player has not been run on a device.

## Tests

From the repository root. The first run registers the addon's classes:

```
godot --headless --path engines/godot --import
godot --headless --path engines/godot -s tests/run_vectors.gd
```

`tests/fixtures/joystick-vectors.json` is generated by the app repo (`npm run vectors`). Do not edit it.
